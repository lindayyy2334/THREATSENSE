Model Pipeline

From raw data
to risk verdict

Four precision-engineered stages transform employee behavioral signals into an explainable threat score in under 50ms.

01

Feature Engineering

Raw timestamps are transformed into behavioral signals. Entry/exit hours, total presence duration, off-hours print ratio, composite risk score. 20+ features extracted per employee per day.

risk_score · presence_hours · ratio_offhours_print
02

Preprocessing & Encoding

Label-encode categorical fields (department, position, campus). Drop leak-prone columns. Apply StandardScaler for Logistic Regression. Stratified train/test split preserves the 95/5 class ratio.

LabelEncoder · StandardScaler · StratifiedSplit
03

Imbalance-Aware Training

class_weight='balanced' for Logistic Regression and Random Forest. scale_pos_weight = 19× for XGBoost. Optimizes for precision-recall in the minority (malicious) class — not overall accuracy.

class_weight='balanced' · scale_pos_weight=19 · PR-AUC
04

Threshold-Optimized Prediction

Decision threshold tuned to ~0.38 (not 0.5) to maximize F1-score on the malicious class. Ensemble of 3 models votes; XGBoost champion is deployed. Score + explanation returned via API.

threshold≈0.38 · XGBoost champion · Explainability

    01 / Model Architecture
    How the model works

    ThreatSense trains three classifiers and selects the best by F1-score on the malicious class:

    • Logistic Regression — pipeline with StandardScaler, class_weight balanced
    • Random Forest — 100 estimators, max_depth 15, balanced weights
    • XGBoost — 200 estimators, scale_pos_weight ≈ 19, eval_metric aucpr

    Features include raw signals (num_print_commands, num_unique_campus) and engineered ones (risk_score, ratio_offhours_print, presence_hours).

    02 / REST API Guide
    Integrate in minutes

    Send a POST request with one day's behavioral data per employee:

    • Endpoint: POST /v1/predict
    • Auth: Bearer token via API key
    • Input: JSON with behavioral fields
    • Output: Risk score, verdict, confidence, signals

    Response time under 50ms. Rate limits: 1,000 req/min on Professional plans. Full OpenAPI 3.0 spec available in the developer portal.

    03 / Metrics & Thresholds
    Understanding the scores

    ThreatSense uses PR-AUC and F1 as primary metrics — not accuracy — because the dataset is heavily imbalanced (~95% normal).

    • AUC-ROC ≈ 0.95 — strong discriminative power
    • PR-AUC ≈ 0.85 — meaningful in the minority class
    • Threshold ≈ 0.38 — tuned to maximize F1

    A lower threshold = higher recall = fewer missed threats (fewer false negatives), at the cost of more false alarms. Adjustable per deployment.

    04 / Deployment Options
    Flexible infrastructure

    • Cloud SaaS — zero infrastructure, instant start
    • Private Cloud — AWS/Azure/GCP VPC isolation
    • On-Premise — Docker/Kubernetes, air-gapped support

    All modes include end-to-end encryption, SOC 2 Type II compliance documentation, and zero data retention by default.
